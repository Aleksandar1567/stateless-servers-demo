Stateless servers

Horizontal scaling works only when any server can handle any request. Both clusters below run the same app code behind a round-robin load balancer. The only difference is where a server keeps your session (who you are, what is in your cart).

      What is going on

      State is data a server remembers between requests, like a login session or a shopping cart. On the left, the server that handled “add phone” stores the cart in its own memory. The next request goes to a different server, which has no cart for you, so you see an empty cart.

      On the right, the cart lives in a shared store (Redis, or a small built-in stand-in). Every server reads the same cart, so the load balancer can send any request to any server.

      Things to try

      1. Press ▶ Play the scenario: add a phone, then open the cart three times.
      2. Log in, then press Open cart a few times. On the left you are logged in on one server only.
      3. Stop (×) the server that holds your cart on the left. The cart is gone for good. Stop one on the right: nothing is lost.
      4. + Add server on the right. It serves your cart immediately. On the left, the new server knows nobody.
